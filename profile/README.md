# Canticle Research

### Independent AI research. Inspectable systems. Evidence before claims.

Canticle is a solo-founded research group studying **AI behavior, safety, memory, models, agents, and emergence**. We build the systems needed to test those questions: persistent memory, evaluation harnesses, research interfaces, and agent infrastructure.

**[SEAM](https://github.com/Canticle-AI-Research/Seam) · [Ghost](https://github.com/Canticle-AI-Research/Ghost) · [Canticle.cc](https://canticle.cc) · [Founder](https://github.com/BlackhatShiftey)**

### Models and behavior

Language models, transformer systems, adaptation, and fine-tuning under explicit workloads. How does behavior change, what caused the change, and can the result be reproduced?

### Memory and time

Persistent context, temporal continuity, source-linked recall, and the limits of reconstruction. Useful memory needs an evidence trail, a way to represent change, and a clear boundary between stored records and derived views.

### Safety and evidence

Provenance, uncertainty, contradiction, prompt-injection containment, privacy, and operator authority. Experiments should preserve their failure modes as carefully as their successes.

### Affect and emergence

How persistent internal state, feedback, learning, and interactions between components affect system-level behavior. Emotion and consciousness remain research questions; behavioral resemblance and model self-report do not establish subjective experience.

### Agent communication

Shared semantics and machine-native communication with explicit meaning, traceability, and policy boundaries, including the problem of hidden or steganographic channels.

## `// SEAM`

### Source-linked memory for agents

SEAM is a local-first memory runtime for durable records, retrieval, and bounded context. Canonical records retain their relationship to source evidence; graph and vector indexes provide derived views that can be rebuilt.

```text
source evidence → MIRL → SQLite
                           ↓
              retrieval → PACK
                     bounded context
```

<p align="center"><a href="https://github.com/Canticle-AI-Research/Seam/blob/main/docs/RAG_ARCHITECTURE.md"><img src="https://raw.githubusercontent.com/Canticle-AI-Research/.github/main/profile/assets/canonical-memory.png" width="100%" alt="SEAM canonical memory: source evidence through RAW, MIRL, SQLite, retrieval and bounded PACK context" /></a></p>

CLI, MCP, REST, and the Textual dashboard provide operator and integration surfaces.

- Persist and retrieve agent memory with provenance
- Inspect records, evidence, temporal history, and graph relationships
- Build bounded context using vector, graph, hybrid, or mixed retrieval
- Evaluate changes with reproducible benchmark artifacts and explicit gates

Current work emphasizes operator setup, distribution boundaries, documentation, and verifiable first-run behavior. The browser WebUI remains a prototype with simulated actions and browser-local state. The `seam-suite` packaging candidate is not a completed production PyPI release.

### A SEAM-backed DeepAgent

Ghost's durable memory is supplied by an authenticated SEAM service. Ghost uses a bounded HTTP interface while SEAM owns the durable memory lifecycle. Conversation checkpoints are kept separately from semantic memory.

Its current command-line surfaces support one-shot and interactive use, memory recall, and operator-scoped file reading and repository search. Shell execution is opt-in, with terminal approval enabled by default. Desktop, expressive-avatar, and voice work remain in development.

<p align="center"><img src="https://raw.githubusercontent.com/Canticle-AI-Research/.github/main/profile/assets/ghost-ensemble.png" width="240" alt="Ghost ensemble — mint-haired girl and her four RGB spirit companions" /></p>

The anime girl and her spirit companions represent Ghost in this profile. The artwork does not imply a shipped avatar interface. The present agent uses configured provider models; a future Ghost LLM remains a research goal.

The longer-term research asks what happens when models, durable memory, feedback, and specialized components operate together over time.

- Can persistent state support measurable continuity beyond a single inference?
- How close can recall and reconstruction get to complete contextual fidelity, and under which resource bounds?
- How do affective-state models influence memory, planning, and response?
- What experiments distinguish emergent behavior from convincing simulation?
- Can AI-to-AI communication remain interoperable while preserving provenance and safety constraints?

These are questions to operationalize and test. They do not imply a trained Canticle foundation model, a completed emotional engine, or evidence of consciousness.

## `// how we work`

**Hypothesis → controlled experiment → preserved evidence → falsification → reproduction → bounded claim.**

Public claims should point to the code, records, and evaluation artifacts that support them. A local test, a merged change, a packaged artifact, and a deployed service are separate milestones. Negative results and unresolved limits belong in the record.
